# EU/Germany Pre-Launch Compliance Pass

A first compliance pass against the GDPR and the EU AI Act covering the items
that needed code (rather than legal text). Six tasks, all merged together.

## What changed

### 1. 16+ age gate moved from self-attestation to verified DOB

- ConsentScreen replaced the "I am at least 16 years old" checkbox with a
  year-of-birth input. Client-side validation rejects under-16 and
  out-of-range values inline.
- POST `/api/v1/consents` now requires a `birth_year` field; service
  validates `1900 ≤ year ≤ currentYear` and `currentYear - year ≥ 16`.
  Returns 422 with `ErrInvalidBirthYear` when violated.
- The `age_16_plus` consent row is still recorded (audit trail) but is
  derived server-side from the verified birth year, not from a checkbox.
- ProfileSetup no longer asks for age — birth year is now collected upstream
  and used by ProfileSetup only to estimate max HR.

### 2. Sign out of all devices

- New `POST /api/v1/auth/revoke-all` endpoint deletes every refresh token
  for the caller. Stateless access tokens still expire on their own 15-min
  TTL.
- New "Sign Out of All Devices" button in Settings, with confirmation alert.

### 3. Push notification consent

- Migration `027_notification_consent.sql`: `notification_preferences.enabled`
  default flipped from `TRUE` → `FALSE`; new `updated_at` column.
- `notifications.Registry` flipped all four types `DefaultEnabled: true` →
  `false`. A user who never toggles a type now never receives that type.
- `SetPreference` writes `updated_at = now()` on every UPSERT — that is the
  consent audit trail.

### 4. AI transparency (EU AI Act Art. 50)

- Persistent "AI" badge next to "Grit" in the chat header and in the home
  GritChatBanner; status line reads "AI Coach · Online".
- "AI" badge in the post-workout review card header.
- One-time `Alert` on first chat open: "Grit's responses are generated by an
  AI model (Google Gemini)... not medical advice." Stored in SecureStore as
  `ai_disclosure_seen_v1` so it appears once per device.
- Italic notice above the Accept button on full-screen proposal review:
  "Generated by AI — please review carefully before accepting."

### 5. Data retention cron

- New `internal/retention` package. Daily ticker runs three purge jobs:
  - `refresh_tokens` older than 30 days past `expires_at`
  - `usage_tracking` older than 13 months
  - `email_otps` older than 1 day past `expires_at`
- Scheduled in `main.go` as a goroutine alongside the existing fact-decay /
  reminder / missed-workout schedulers.

### 6. GDPR Art. 15/20 data export

- New `internal/services/export.go` builds a single `ExportPayload` with
  every user-scoped row: profile, consents, programs/phases/weeks/scheduled
  activities, program criteria, workouts, chat messages/segments/facts,
  notification preferences, usage tracking. Operational artefacts (token
  hashes, OTP codes) are deliberately excluded.
- New `GET /api/v1/users/me/export` endpoint returns the JSON as an
  attachment.
- New "Download My Data" button in Settings uses RN's built-in `Share` API
  (no new deps) to hand the JSON to the OS share sheet.

## Deferred (out of scope for this pass)

- Filling Impressum placeholders (legal name, address, USt-ID) — user wants
  to do this when the data is available.
- Adding Google Gemini, Expo Push to the privacy policy as subprocessors
  with US-transfer disclosure (SCCs/DPF) — content change, not code.
- Withdrawal-instructions (Widerrufsbelehrung) for Premium — pending Stripe
  integration.
- German translations of Terms + Privacy — only required when the app or
  marketing actively address the German market in German.
- Inactive-account purge (delete after N months no-login) — sensitive
  retention rule, deferred until exact period is decided.
- Internal Verzeichnis von Verarbeitungstätigkeiten + breach response
  runbook — not user-facing.
